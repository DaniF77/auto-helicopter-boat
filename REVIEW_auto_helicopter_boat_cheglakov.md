## 3. Замечания

### R-01. Противоречие: TC-34 в `TEST_CASES.md` не совпадает со `SPEC.md` и тестом

| Поле | Значение |
|---|---|
| **ID** | R-01 |
| **Severity** | Critical |
| **Категория** | Противоречие |
| **Расположение** | `TEST_CASES.md`, TC-34; `SPEC.md`, сценарий 4.4; `test_TC_34_out_of_energy_before_takeoff` |
| **Статус** | Открыто |

**Описание.**  
В `TEST_CASES.md` для TC-34 указано: «второй `move` — `BoatOutOfEnergy`». Однако по `SPEC.md` (сценарий 4.4) и по тесту:
1. `switch_mode("air")` → `energy = 2`;
2. **первый** `move(1, "air")` → `BoatOutOfEnergy`;
3. `refuel(50)` → `energy = 52`;
4. **второй** `move(1, "air")` → успешен, `energy = 49`.

Тест `test_TC_34_out_of_energy_before_takeoff` проверяет именно эту последовательность: первый `fly(1)` падает, второй после заправки succeeds.

**Рекомендация.**  
Исправить формулировку в TC-34: «первый `move` — `BoatOutOfEnergy`, второй `move` успешен». Проверить, что ожидания в TC-34 полностью совпадают со SPEC 4.4.

### R-02. Непокрытые граничные случаи и порядок исключений в `switch_mode`

| Поле | Значение |
|---|---|
| **ID** | R-02 |
| **Severity** | Major |
| **Категория** | Непокрытые случаи / граничные значения |
| **Расположение** | `SPEC.md` 3.4.1 и раздел 5; тесты TC-10, TC-11, TC-12 |
| **Статус** | Открыто |

**Описание.**  
SPEC требует:
- переключение в тот же режим ничего не меняет и не тратит энергию;
- энергия ровно равна стоимости — переключение разрешено;
- сначала проверяется допустимость `new_mode`, потом энергия.

В тестах покрыто:
- same mode только при `energy=100` (TC-11);
- нехватка энергии при `energy=4` (TC-12);
- неизвестный режим при `energy=100` (TC-10).

Не покрыто:
1. `energy=0; switch_mode("water")` — не должно быть исключения, энергия остаётся 0.
2. `energy=5; switch_mode("ground")` — ровно хватает, энергия должна стать 0.
3. `energy=0; switch_mode("space")` — должен быть `ValueError`, а не `BoatOutOfEnergy` (порядок проверок).

**Рекомендация.**  
Добавить 2–3 теста:
- `test_TC_12a_same_mode_with_zero_energy_does_nothing`;
- `test_TC_12b_switch_with_exact_energy_allowed`;
- `test_TC_10a_unknown_mode_checked_before_energy`.
Уточнить в `TEST_CASES.md` ожидания для этих границ.

### R-03. Непокрытые случаи в `calculate_energy`, `refuel` и приоритет `BoatSinks` над `BoatOutOfEnergy`

| Поле | Значение |
|---|---|
| **ID** | R-03 |
| **Severity** | Major |
| **Категория** | Непокрытые случаи / негативные сценарии |
| **Расположение** | `SPEC.md` 3.4.2, 3.4.3, 3.4.5; тесты TC-24, TC-30 |
| **Статус** | Открыто |

**Описание.**  
Не покрыто:
1. `calculate_energy(0, "water")` и `calculate_energy(-1, "water")` — SPEC 3.4.3 требует `ValueError` при `distance_km <= 0`, а TC-24 проверяет только неизвестную среду.
2. `refuel(-1)` — SPEC 3.4.5 требует `ValueError` при `amount <= 0`, а TC-30 проверяет только `0`.
3. Приоритет исключений в `move`: тяжёлая лодка с недостатком энергии — `mass_kg=2000`, `hull_volume_m3=1`, `energy=5`, `move(10, "water")`. По SPEC 3.4.2 `BoatSinks` должен возникать раньше `BoatOutOfEnergy`, но этот приоритет тестами не зафиксирован.

**Рекомендация.**  
Добавить тесты:
- `test_TC_24a_calculate_energy_zero_distance_raises_value_error`;
- `test_TC_24b_calculate_energy_negative_distance_raises_value_error`;
- `test_TC_30a_refuel_negative_amount_raises_value_error`;
- `test_TC_21a_sinks_checked_before_energy`.
Обновить `TEST_CASES.md` соответствующими ID.

### R-04. Неоднозначность валидации `name` и непокрытая зависимость от `max_speed_kmh`

| Поле | Значение |
|---|---|
| **ID** | R-04 |
| **Severity** | Minor |
| **Категория** | Неоднозначность / покрытие |
| **Расположение** | `SPEC.md` 3.2; все тесты используют `max_speed_kmh=100` |
| **Статус** | Открыто |

**Описание.**  
Две связанные проблемы:
1. В SPEC указано, что `name` — «непустая строка». Не уточнено, считается ли строка из пробелов `"   "` пустой. TC-01 проверяет только `""`. Это оставляет неоднозначность поведения.
2. Все тесты движения используют `max_speed_kmh=100`, поэтому формулы скоростей из SPEC 3.4 (`water = max*0.5`, `ground = max*0.8`, `air = max*1.0`) фактически не проверяются. Например, при `max_speed_kmh=50` `move(10, "water")` должен вернуть `0.4`, а не `0.2`.

**Рекомендация.**  
- Явно зафиксировать в SPEC, тримится ли `name` и допустима ли строка из пробелов; добавить соответствующий тест.
- Добавить один тест с `max_speed_kmh != 100` (например, `50`) для проверки времени движения во всех режимах или хотя бы в одном.
